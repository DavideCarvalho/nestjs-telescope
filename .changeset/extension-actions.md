Extension row actions and dev tools. `TelescopeExtension.actions()` declares write actions and a table column's `action` puts a button on matching rows (`showWhen`, input filled from the row). The dashboard asks for confirmation, then calls `POST <path>/api/ext/:ext/actions/:action` with `{ confirmed: true, input }`. Like every console mutation it needs `mutations: true`, passes the console's `authorize`, is refused from one organization's view, and writes an audit line with the caller through the `TelescopeAudit` logger: the signed-in user (`request.user`, the user an `authorize: { policy, ability }` check got from `getUser`, or the session's user), else a hash of the bearer token, else `console-session` when `authorize` allowed the request, else `anonymous`. `TelescopeExtension.devTools()` adds tools next to telescope's own on the dev MCP endpoint, each served as `telescope_<name>`; a tool with an invalid name or shape, or a name already served, is left out with a warning so telescope's own tools are still served, and `action` tools are audited the same way. `/api/meta` now lists `actions` and `mutations`. The controller also resolves `ModuleRef` explicitly, so `ctx.moduleRef` is set in extension providers whatever the build's decorator metadata.
